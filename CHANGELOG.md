# Change Log

## [2.5.0]

- **CFC charts in the graphical preview** — CFC chart files (`*.cfc.xml`, TIA Portal V21, as CMsoft Import for TiaPortal exports them into the `Charts` folder of the PLC) open like a block: the partitions **A, B, C …** as tabs, the sheets of each partition (1 … 6) one below the other, the blocks and nested charts with their pins, values and comments, the text boxes, and the connections drawn like in the TIA Portal CFC editor — at right angles, in staircases that do not cross where they need not, with the sheet bars at the edges and colors by data type. A click on a sheet bar entry goes to the other end of the connection — another partition or another chart file — and selects the pin there, as TIA Portal does; a click on a line highlights the whole connection. Right-click a block for **Open block** (its FB or FC) and **Go to Source Line** (its line in the chart file); instructions and nested charts offer **Go to Source Line** too.
- **CFC charts in the HTML and web previews (PRO)** — **Generate HTML preview file** writes the page of a chart, and **Generate Web Preview** puts the `Charts` folder into the navigator tree; there the chart pages link each other and the pages of the blocks they use.
- **The preview says what TIA Portal would refuse** — every graphical preview (LAD, FBD, STL, SCL, GRAPH, CFC, data blocks and data types) checks its file when it opens: a strip above the drawing shows *No problems found for the export to TIA Portal*, or the errors and warnings with their lines, and marks the networks, boxes, steps and chart blocks they concern (a network that holds one is marked while it is collapsed, too). A click on a finding shows it in the drawing, *line N* opens the file there, *Show in PROBLEMS* lists all. Nothing to click to start it, and it needs no TIA Portal: XML that breaks off (in English, with line and position), IDs and UIds used twice, wires to elements a network does not have, call pins the call does not declare, GRAPH steps and transitions numbered or named twice and connections to steps that do not exist, members declared twice, and in `.scl`, `.s7dcl`, `.db` and `.udt` sources blocks, `VAR` sections, `STRUCT`, `REGION`, `IF` … and networks that are not closed, comments and texts that are not closed. CFC charts are checked with the rules of the CFC export of CMsoft Import for TiaPortal 4.11 or newer when it is installed. Every real TIA Portal export passes without a finding. FREE.
- **Findings in PROBLEMS** — the same check runs when a TIA file is opened or saved in an editor, and when a file that is open or has findings changes on disk (also one an AI agent writes): its entries ("Check before export") are in PROBLEMS on their lines.
- **A file the preview cannot draw** — the page says why (the findings of the check, e.g. the line where the XML breaks off) instead of a message in the language of Windows, and the preview draws the file again as soon as it is saved fixed.
- **The preview follows its file** — when the file changes on disk, the preview draws it again (a *Review last changes* preview only checks it again).
- **CMsoft Import for TiaPortal 4.11 asks before an export** — its *Export to TIA Portal* commands use this check: with errors it asks whether to export all files, only those without errors, or none - it never blocks the export.

## [2.4.0]

- **Web preview of WinCC Unified HMI screens (PRO)** — **Generate Web Preview** on the project folder of a CMsoft Import for TiaPortal export (or on `Devices`, `HMIs`, or one HMI device folder) now builds the preview of the whole project: the navigator tree shows the **PLC** and every **HMI** as devices of their own, and each screen of a WinCC Unified HMI is shown in the browser. The preview draws rectangles, texts, IO fields, buttons, circles, polygons, bars, gauges, screen windows, pop-up screens and the alarm view are drawn from the exported screen files; tag dynamizations (mapping tables with ranges and bits, flashing) and the JavaScript of the buttons and screens runs in the browser with screen changes, pop-ups, tag writes and item properties. A project with several PLCs and HMIs goes into one preview: the folder of every device in the tree starts with **Online** — a session (address, user, *Go online*) for a PLC and one for each PLC connection of an HMI, the addresses of the HMI connections filled in, a dot showing the state — and every page reads and writes only through the sessions of its own device, so an HMI with connections to several PLCs reads and writes each tag through its own connection. Below **Online**, every HMI has a **Start** button that opens the HMI on the start screen set in its runtime settings in TIA Portal. Without a connection (offline, or the PLC not answering) the screens are greyed out with *No connection to the PLC* and the reason; when only some connections of an HMI are online, only the objects of the others are greyed out. The HMI page switches between **Operate** (buttons and input fields write to the PLC) and **Monitor** (read only) and between fitting the screen into the page and its real size. Faceplates and the pop-ups of faceplate types from the library are not supported; they, trends and dynamic widgets appear as labelled frames, and the toolbar lists them together with any script error.
- **Web preview: built-in functions and script modules of the HMI scripts** — the scripts of the screens and the script modules of a WinCC Unified HMI (`Scripts/` of the export) run in the browser with the built-in functions of the WinCC Unified runtime: `Tag.SetBit` / `ResetBit` / `Increase` / `Decrease`, the tag system functions (`SetTagValue`, `IncreaseTag`, `SetBitInTag`, `InvertBitInTag`, `ShiftAndMask`, the *ReadAnd…* functions), tag sets, `UI.DataSet` and `Screen.DataSet`, `Screen.CurrentWindow` / `ParentScreen`, the screen and pop-up functions with the order of parameters WinCC uses (caption, toggle, position), `SetPropertyValue` / `GetPropertyValue`, the screen history, `Alarming.GetActiveAlarms`, timers and colors; `HMIRuntime.Language` is the LCID (1033) as in WinCC. Only the functions the scripts of an HMI use go into its page (`hmi-api.js`). Bits and increments are computed from the current value of the tag in the PLC — never from a value the preview does not know, which would clear the other bits — and Monitor mode still blocks every write. Functions of the operator panel, users, databases and logging are noted under *About this preview* instead of stopping the script.
- **Fixed: alarm filters of the HMI screens** — a filter a script sets on the alarm view (filter buttons of an alarm screen) is applied at once, and filters use the whole syntax of WinCC Unified: `IN (…)`, `NOT IN`, `LIKE` / `NOT LIKE`, `BETWEEN`, `&&` / `||`, wildcards `*` and `?`, and the alarm texts `AlarmText1` … `AlarmText9`; before, such a filter showed every alarm or none.
- **Web preview: graphics of the HMI screens** — graphic views, buttons and screen backgrounds of a WinCC Unified HMI show their project graphics (Languages & resources > Project graphics) instead of the graphic's name, in the language picked in the toolbar and stretched as configured. The graphics come from the export of CMsoft Import for TiaPortal (**Import Project Graphics**, or with the HMI); EMF and WMF graphics are converted to PNG for the browser. A graphic the export lacks is still shown by its name and listed in the warnings of the page.
- **Web preview: accepting the certificate of the CPU** — when **Go online** or **Test connection** in a web preview cannot reach the CPU, mostly because the browser does not trust its self-signed certificate yet, a dialog offers **Open the CPU page**: the security warning of the browser opens in a window of its own, you accept the certificate there once (*Advanced*, then *Proceed to …*), and the preview closes the window and finishes going online — or the connection test — by itself.
- **What's New** — after an update the extension opens the *What's New* tab once: the new functions of the version, with links to their sections of the user manual, and the video of the CMsoft channel on YouTube in which the code of a TIA Portal project and its WinCC Unified HMI are opened in VS Code and in the browser (the README shows it too). **CMsoft Viewer for TiaPortal: What's New** opens the tab again; a new installation does not open it by itself.
- **Fixed: Generate Web Preview took many minutes on large projects** — the wiring of the call pins, which only the *Sequence control* panel of GRAPH sequences needs, was collected for every FB call and carried by every page: on a plant with many FB calls and multi-instances the preview took up to half an hour. It is collected for the calls of sequencer FBs only now (GRAPH blocks and FBs with the sequencer input `INIT_SQ`), and such a preview is ready in under a minute.
- **Faster online values in large blocks** — the graphical preview in VS Code and the web preview read only the variables you see: the rows of collapsed structures and the operands of closed networks are left out (the GRAPH states, the *Sequence control* panel and the trend chart are always read). An FB with many multi-instances has thousands of interface rows and the web API of the CPU needs a few milliseconds per variable, so the values now refresh much faster; expanding a structure or opening a network brings its values with the next reading.
- **Fixed: MCP calls longer than 5 minutes lost their answer** — the MCP server answered a tool call as plain JSON only when the tool had finished, and MCP clients on Node's fetch (the MCP SDK and the agents built on it) give up after 5 minutes. The answer is an event stream (`text/event-stream`) with a keep-alive line every 15 seconds now; the example clients of the manual read both forms.
- **Fixed: Generate HTML preview file from the Command Palette** — with the graphical preview of a block active, the command answered *Select a local block source first*; it now takes the block of the active preview, like the other commands of the preview.
- **Fixed: Refresh license status with an active license** — in a VS Code profile without a recorded acceptance of the license terms it answered *Accept the license terms (EULA) first*, but the License page shows the terms only without a license. It now renews the key and reports the license as up to date; started from the Command Palette, its message no longer gets lost while the page opens.

## [1.1.87]

- **Review last changes** — a graphical git diff for PLC blocks: right-click a block source in the Explorer (`.s7dcl`, `.xml`, `.db`, `.scl`, `.udt`) → **Review last changes** opens the graphical LAD/FBD preview with the changes highlighted. The review basis is the working tree vs git HEAD (uncommitted changes) when there are any, otherwise the last commit that touched the file (an information message names the shown commit; a single-commit file is shown as fully added). Added/changed elements — gates, call boxes, contacts/coils and operand labels (variable names) — are drawn **green**; deleted content is **red**: a deleted rung merges back into its network and is drawn in place with red gates, labels and wires (a deleted pin on a surviving box is restored so the red wire keeps its original endpoint), a wholly deleted network appears as a red dashed "Deleted network" section at its original position, and deletions that cannot be rendered (e.g. a single pin line) mark the neighboring element red. SCL/STL networks (including SCL inserts in FBD/LAD blocks) show a git-style line diff instead: added code lines with a green background and a `+` gutter, deleted lines inserted from the old version with a red background and a `−` gutter. The `.s7dcl` parser now captures per-element and per-pin source lines (previously one line per rung), so the highlighting points at the exact element that changed — "Go to Source Line" benefits from the same precision.
