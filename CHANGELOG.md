# Change Log

## [2.1.0]

- **New name: CMsoft Viewer for TiaPortal** — the extension formerly called *TIA Viewer* is now *CMsoft Viewer for TiaPortal*: the commands (*CMsoft Viewer for TiaPortal: …*), the Copilot tools, the Output channel and the user manual carry the new name. The extension ID (`MariuszCzyrnek.tia-viewer`), the command IDs, the settings (`tiaViewer.*`) and the generated files stay the same.
- **New icon** — the CMsoft cloud with *cm* and *Viewer* in mint.
- **Documentation without the sources** — the README no longer lists Node.js and the .NET SDK among the requirements (they were needed only to build the extension) and no longer describes the internal programming interface of its library; the user manual prints its two MCP example clients in full instead of pointing to a folder that is not part of the extension. A missing viewer library asks to reinstall the extension instead of naming a build command.
- **FREE and PRO** — FREE keeps the graphical LAD/FBD/SCL/GRAPH preview in VS Code, Review last changes, the SVGHMI preview, the user manual and the editor features; PLC Online in the preview is limited to **1 minute per connection** (going online again starts a new connection) and the online trend chart to **1 variable**. **PRO** unlocks **Generate HTML preview file**, **Generate Web Preview**, unlimited PLC Online, trend charts with up to 10 variables, the Copilot tools, the MCP server and the WinCC SVGHMI widgets. The license panel (**CMsoft Viewer for TiaPortal: Manage License / Subscription**) offers a free 14-day trial and the purchase of a subscription or a one-time license, with a 14-day money-back guarantee; each license covers one computer ([Terms of Sale](TERMS.md)). The **CMsoft** item in the status bar lists the licenses of all installed CMsoft extensions. See [README → FREE and PRO](README.md#free-and-pro).
- **WinCC SVGHMI widgets from S7-GRAPH sequences (PRO)** — new command **Generate WinCC SVGHMI (GRAPH)** (Explorer right-click on GRAPH block exports or a folder, plus an editor-title button while the graphical preview shows a GRAPH block): every GRAPH sequence is written as a dynamic SVG widget (`GRAPH_<block>[_Seq<n>].svghmi`) for **WinCC Unified** and **WinCC V8** — the TIA-like sequence chart of the viewer, built to the Siemens dynamic SVG rules. The step and transition states are widget parameters bound to the instance DB of the GRAPH FB: `<step>_X` (active → green), `<step>_LA` (interlock not fulfilled → yellow), `<step>_VA` (supervision fault → red), `<transition>_TT` (fulfilled → green bar); all colors are `HmiColor` parameters. On WinCC Unified Runtime a tap on a step opens its view (interlock and supervision networks with the live state of every operand, action table, **Enable step** / **Disable step**) and a tap on a transition its condition network; GRAPH FBs with the standard sequencer interface get a mode header and the **Sequence control** station (Initialize, Deactivate all, Acknowledge, Automatic / Semiautomatic / Manual mode, Next, manual step selection). The export also writes **`<widget>.bindings.json`** next to the GRAPH export: the tag of every parameter for each instance of the FB. New settings `tiaViewer.svghmi.outputFolder`, `tiaViewer.svghmi.stepFaultStates`, `tiaViewer.svghmi.transitionStates`, `tiaViewer.svghmi.detailViews`, `tiaViewer.svghmi.sequenceControl` and `tiaViewer.svghmi.bindingsFile`.
- **SVGHMI preview** — `.svghmi` files (WinCC Unified / WinCC V8 dynamic widgets, generated here or from widget libraries) open in an interactive preview: the widget is drawn like the WinCC runtime draws it, with every `hmi-bind` expression evaluated against the parameter values of a side panel (checkboxes, number fields, color pickers; click a shape to list its parameters, double-click toggles its first Boolean parameter), zoom/fit and WinCC-like screen backgrounds. The widget's actions run in the preview, and a findings list checks the file against the Siemens SVGHMI rules. Edits of the XML re-render live. New command **Open SVGHMI Preview**; the SVGHMI export offers **Open Preview**.
- **User manual in VS Code** — **CMsoft Viewer for TiaPortal: Open User Manual** opens the English manual in VS Code's Markdown preview (optionally at a section such as `"10.2"`), **CMsoft Viewer for TiaPortal: Search User Manual** lists every chapter and section. The **CMsoft** item in the status bar and **Help: CMsoft Manuals…** list the manuals of all installed CMsoft extensions.
- **PLC certificates: trust on first use** — the VS Code preview no longer accepts whatever certificate a PLC presents. The first connection to a CPU (**Go online** or **Test connection**) shows the SHA-256 / SHA-1 fingerprint, subject and validity of its certificate and asks you to trust it; the decision is kept per PLC address and checked on every connection. A CPU that later presents a different certificate is refused with a warning until you trust the new one (expected after a new certificate was loaded into the CPU in TIA Portal or the CPU was replaced). Certificates Windows trusts — e.g. issued by the TIA Portal project CA whose root you installed — are accepted without asking. Nothing, not even the password, is sent over a refused connection; the AI tools only report the refusal. New command **CMsoft Viewer for TiaPortal: Manage Trusted PLC Certificates** forgets trusted certificates. The connection to the PLC uses TLS 1.2 only.
- **PLC passwords per PLC and user** — the preview remembers the web API password separately for every PLC address and user instead of one password for all PLCs, so a remembered password is never offered to, and sent to, another PLC; a password filled in from the store is cleared as soon as the address or user changes. The new command **CMsoft Viewer for TiaPortal: Forget Saved PLC Passwords** lists the remembered passwords and forgets the ticked ones.
- **Command Palette** — **Open source file**, **Graphical preview LAD/FBD**, **Review last changes** and **Generate Web Preview** run from the Command Palette work on the file of the active editor — a text editor or a graphical preview — instead of asking for a selection in the Explorer.
- **PLC online tools: one access check with the preview** — `#plcRead` / `#plcWrite` and their MCP counterparts check **Accessible / Writable from HMI/OPC UA** with the same rules as the interface table of the preview, so the tools and the write popup can no longer disagree. A whole structure or array is refused with a reason — read or write its members or elements one by one.
- **Your logo in the web preview** — the navigator of **Generate Web Preview** shows a logo in its top-left corner, above the PLC name and the block tree: the CMsoft logo by default, or your own PNG image (e.g. your company logo) set in the new setting `tiaViewer.webPreview.logoFile`.
- **Faster previews** — the viewer scripts and styles are loaded once per session, the FB instance map of a PLC folder is reused while its sources are unchanged, and the web preview indexes the type and tag sources once per PLC instead of once per block.
- **Security** — the MCP server refuses requests whose `Host` or `Origin` header is not a loopback address (DNS rebinding) and request bodies over 1 MB, compares its token in constant time and keeps at most 32 sessions; the workspace copy of `.tia/mcp-viewer.json` is git-ignored, so the token is not committed with the TIA project. The whole-PLC web preview accepts PLC writes, watch subscriptions and trend messages only from its own pages.
- **The CMsoft shop has its own address** — the README and the documents that ship with the extension (End User License Agreement, Terms of Sale, Privacy Policy) point to <https://shop.cmsoft.com.pl>: the extension's page, the plans and the Terms of Sale, Refund and Privacy policies. The terms of the documents are unchanged.
- **The disclaimer of liability in the user manual** — the user manual sums up sections 12–14 of the End User License Agreement in section 18.9 (*Disclaimer of liability*), warns in section 2.7 and says in the new section 15.7 that what an AI assistant reads out, suggests or writes is not reviewed or verified by CMsoft. The README's *Disclaimer of Liability* follows the agreement: liability is excluded or limited to the extent permitted by law, and liability that the law does not allow to exclude and the rights of consumers are not affected; it also names the MCP server. In section 18.8 of the manual, the reference to the sections of the license terms no longer links to chapters 12 and 14 of the manual. The terms of the documents are unchanged.
- **Fixed: Export CSV, Save config and Load config of the trend chart did nothing in VS Code** — the buttons now open VS Code's save / open dialog (a CSV up to 64 MB, a configuration up to 1 MB) and a notification names the saved file; **Export CSV** on an empty chart says that there is nothing to export. CSV fields that contain quotes or commas — TIA names such as `"TestPID1_DB"."SP"`, indexes of multi-dimensional arrays — are quoted as RFC 4180 requires, so spreadsheet programs keep the columns (also in the web preview).
- **Fixed: going offline cleared the trend chart** — **Go offline** now stops the recording and keeps the samples: the chart marks the pause with a gap and says that the samples stay, **Export CSV** still exports them and **Clear** removes them. The same in the web preview.
- **Fixed: trend chart in a narrow editor** — the toolbar wraps onto a second row and the legend onto several rows instead of being cut off at the right edge.
- **Fixed: the PLC Online tab covered the User field** of the slide-out panel in the graphical preview.
- **Fixed: GRAPH step and transition views behind the Sequence control panel** — the view opened under the panel, with its close button out of reach; it now opens above it.
- **Fixed: Sequence control used an instance DB that is never called** — when the FB that calls a GRAPH FB has several instance DBs and only some of them are called (e.g. `SeqPrep_IDB` called, `SeqPrep_DB` not), the variables wired to the GRAPH call pins were resolved through every instance; now only through the called ones (through all of them when no call is found). This changes the write targets of the **Sequence control** panel.
- **Fixed: recording started by an AI agent did not reach the preview** — the first `record` of `#plcTrendData` (or the MCP tool `tia_viewer_trend_data`) in a session now reaches every open graphical preview, and previews opened later pick up the running recording, so the archive fills without opening the trend chart.
- **Fixed: native module repair notification** — when the edge-js native modules fail to load, the notification names this extension and **Show Logs** opens its log (it called a command of the TIA Portal import extension before).
- **Fixed: MCP** — the confirmation of a PLC write requested by an MCP client shows the variable with its quotes once (`"TestPID1_DB"."SP"`; the quotes were doubled). The workspace copy of `.tia/mcp-viewer.json` is written as soon as a graphical preview opens in the window, so a client that looks for it in the workspace finds it. VS Code's Copilot no longer lists every tool twice: the MCP server is no longer offered to VS Code, which has the same tools as language model tools; other MCP clients read `.tia/mcp-viewer.json` as before.
- **Fixed: web preview** — the start page of the navigator is in English like the rest of the web preview (it was in Polish). When the browser cannot reach the PLC at all ("Failed to fetch"), the message says what to check: open `https://<PLC address>/` once in that browser and accept the certificate of the CPU, CORS enabled on the CPU, the network route to it.
- **Fixed: robustness** — malformed PLC answers nested very deeply no longer crash the VS Code extension host; messages about supported files list every block format (SimaticML XML, `.s7dcl`, `.db`, `.scl`, `.udt`).

## [2.0.1]

- **MCP server (Streamable HTTP)** — the extension now runs a localhost-only MCP server (`http://127.0.0.1:<port>/mcp`) that exposes the four `tia_viewer_*` PLC online tools (sessions, read, write, trend data) to any MCP client — VS Code Copilot (auto-discovered on 1.99+ via the MCP server definition provider), Claude Desktop or custom agents. The endpoint URL and per-start Bearer token are written to `.tia/mcp-viewer.json` (extension global storage, plus the workspace once it is used for TIA work); `GET /health` returns the tool list without auth. New settings `tiaViewer.mcp.enabled` (default on) and `tiaViewer.mcp.writeWorkspaceStateFile`, new command **TIA Viewer: Start MCP Server**. PLC writes requested by an MCP client are confirmed by the local user with a modal dialog unless `tiaViewer.lmTools.autoConfirmPlcWrites` is enabled; the tools work exactly like the Copilot language model tools.

## [1.1.87]

- **Review last changes** — a graphical git diff for PLC blocks: right-click a block source in the Explorer (`.s7dcl`, `.xml`, `.db`, `.scl`, `.udt`) → **Review last changes** opens the graphical LAD/FBD preview with the changes highlighted. The review basis is the working tree vs git HEAD (uncommitted changes) when there are any, otherwise the last commit that touched the file (an information message names the shown commit; a single-commit file is shown as fully added). Added/changed elements — gates, call boxes, contacts/coils and operand labels (variable names) — are drawn **green**; deleted content is **red**: a deleted rung merges back into its network and is drawn in place with red gates, labels and wires (a deleted pin on a surviving box is restored so the red wire keeps its original endpoint), a wholly deleted network appears as a red dashed "Deleted network" section at its original position, and deletions that cannot be rendered (e.g. a single pin line) mark the neighboring element red. SCL/STL networks (including SCL inserts in FBD/LAD blocks) show a git-style line diff instead: added code lines with a green background and a `+` gutter, deleted lines inserted from the old version with a red background and a `−` gutter. The `.s7dcl` parser now captures per-element and per-pin source lines (previously one line per rung), so the highlighting points at the exact element that changed — "Go to Source Line" benefits from the same precision.

## [1.1.54]

- **Code folding in the text editor** for SCL and s7dcl sources: gutter fold markers (+/…) for whole `IF`/`FOR`/`WHILE`/`REPEAT`/`CASE` blocks, `REGION` and `NETWORK`…`END_NETWORK`. Case-insensitive, and keywords inside comments or string literals never start a fold.
- **SCL highlighting in the previews now mirrors the text editor palette**: the .NET SCL highlighter classifies tokens into the same categories as the editor grammar — control keywords (IF/FOR/WHILE/…, purple like `keyword.control`), declarations/blocks/word operators (AND/OR/NOT/…, blue), data types (Int, Bool, … — newly highlighted) and constants (TRUE/FALSE) — and `viewer.css` maps them to the Dark+/Light+ token colors of the matching TextMate scopes (overridable via the `--plc-scl-*` variables). Keyword bold was dropped to match the editor.
- **Syntax highlighting in the text editor** for TIA Portal exports: declarative TextMate grammars (same mechanism as the C/C++ / C# extensions) for `.scl` (`tia-scl`), `.s7dcl` (`tia-s7dcl`), `.db` (`tia-s7db`) and `.s7res` (`tia-s7res`) — SCL keywords and control flow, block/VAR-section declarations, data types, `S7_*`/HMI attribute blocks, based and time literals (`16#…`, `T#…`), strings, comments, `#local` variables, `NETWORK`/`RUNG` structure with `wire#…` identifiers, SD logic elements (`A`/`O`/`X`, `S_SR`, comparators, edge triggers, contacts/coils) and multilingual resource entries. Applies when a source is opened as text (**Open source file** / **Open With…** → **Text Editor**); the graphical viewer remains the default editor. File associations can be changed with the standard `files.associations` setting and token colors via `editor.tokenColorCustomizations` (see README → Syntax highlighting).

## [1.1.43]

- "Sequence control" panel for GRAPH sequencer FBs (VS Code graphical preview and whole-PLC web preview): on FB pages whose interface carries the standard sequencer inputs (`INIT_SQ`, `OFF_SQ`, `ACK_EF`, …), a floating, draggable panel — styled after the TIA test panel — offers **Initialize**, **Deactivate all**, **Acknowledge -(V)-**, the mode radios Automatic / Semiautomatic (+ **Ignore transition**) / Manual (+ **Next** and manual step selection with **Enable**/**Disable**). Actions pulse the corresponding sequencer input of the instance picked in the instance picker (edge-triggered: write TRUE, then FALSE); the mode radios follow the polled `AUTO_ON`/`TAP_ON`/`TOP_ON`/`MAN_ON` outputs. The panel requires an online PLC session and writes through `PlcProgram.Write`. Writes do not target the instance DB directly (sequencer inputs are typically not writable there); instead the panel detects the variables wired to the pins of the sequence call (e.g. `"SEQ_IDB"(INIT_SQ := #INIT_SQ)` in the calling block) and writes through them (`"SeqPrep_IDB"."INIT_SQ"`); a pin without wiring falls back to the direct IDB write. The status line shows the actual PLC variable written.

## [1.1.33]

- Copilot language model tools for PLC online access: once you go online in a graphical preview (PLC Online → **Go online**), GitHub Copilot can work with the PLC through four new tools — `#plcSessions` (list PLCs with an active online session), `#plcRead` (read online variables), `#plcWrite` (write one online variable, with a per-write confirmation unless `tiaViewer.lmTools.autoConfirmPlcWrites` is enabled) and `#plcTrendData` (archived trend series). The tools reuse the panel's shared PLC session and never see your credentials. Data-block variables (`"DB"."Member"…`) are checked against the exported block sources in the workspace before any access: reads require the **Accessible from HMI/OPC UA** attribute, writes require **Writable from HMI/OPC UA** — with the same inheritance rules as the interface table (Temp/Constant sections and complex InOut members are excluded); block exports are found anywhere in the workspace (`Program blocks`, `Units/<unit>`, `Technology objects` or loose PLC folders). `#plcTrendData` can also **start recording variables autonomously** (`action: "record"`, optionally mirrored onto the trend chart with `showChart`) and stop it (`action: "clear"`), so agentic workflows like PID tuning — record setpoint/process value/output, read the step response, adjust `Gain`/`Ti`/`Td`, repeat — run without any further user interaction beyond the initial Go online and the write confirmations.

## [1.1.19]

## [1.1.1]

- Fixed HMI attribute flags (Accessible/Writable/Visible/Setpoint) in the interface table for S7 source exports (`.s7dcl`/`.scl`/`.udt`) — the decoding now matches the TIA Portal interface editor: a member is fully HMI-accessible by default, also when its attribute block carries only `S7_MLC` texts (previously such members showed no flags at all); `S7_Visibility := "Hidden := External"` clears Accessible/Writable/Visible, `S7_Visibility := "Unlisted := External"` clears only Visible (was ignored), `S7_Access := "ReadOnly := External"` clears Writable, and Setpoint defaults to off (was on for attribute-less members). Temp and Constant sections no longer show HMI flags (greyed out in TIA), and the FC `Ret_Val` row gets the default fully-accessible flags.

## [1.1.0]

- Online trend chart in the whole-PLC web preview: right-click a variable row on a data block (DB/IDB) page → "Add to chart" opens a uPlot-based live trend in the split view, fed by the PLC Online session (a timestamped sample on every poll, also in on-change mode); the menu also offers assigning the series to an existing Y axis or a newly created one (up to 5 axes, extras stacked on the right). Up to 10 series, ring buffer trimmed by the configurable max recording time (default 10 min, new "Trend" panel in the navigator sidebar — retention only), BOOL values charted as 0/1. The displayed time window is set independently on the chart toolbar (default 30 s, clamped to the retention) and auto-scrolls with the live edge (pan ◀/▶ to freeze, "Follow" to re-attach); drag-selecting a range zooms the chart to it and mirrors the span into the window field, double-click returns to live follow. The legend shows cursor values and its labels toggle series visibility. Toolbar: pan/window/follow, pause, clear, CSV export, save/load chart configuration as JSON (incl. axis assignments).
- PLC Online live monitoring on data block pages (global DB / instance DB, incl. technology object instance DBs) in the whole-PLC web preview: the interface table gains a "Monitor value" column next to the variable name, showing online values for variables with the `ExternalAccessible` attribute ("Accessible from HMI/OPC UA"). The flag is inherited into expanded structs/UDTs/multi-instances, and arrays of elementary types are monitored per element (up to 256 elements). Reuses the watch-table live protocol — no extra setup beyond the existing PLC Online panel.
- Expanded UDT/struct/FB-instance rows now show the attribute flags (Accessible/Writable/Visible/Setpoint) as set in the type source: DB exports inline the instance interface without member attributes, so the missing flags are merged from the UDT/FB export by member/section name (explicit inline values win). Type references written bare (`Datatype="Filter_PT2"`, unquoted — typical for V21 exports) now resolve as well.
